# Building ShieldBar

ShieldBar has two application builds and one shared privileged helper:

| Component | Stack | Output |
| --- | --- | --- |
| Native macOS app | Swift, SwiftUI, AppKit, WebKit | `ShieldBar.app` (arm64) |
| Windows/Linux app | Electron, TypeScript, React | NSIS, zip, AppImage, `.deb` (x64) |
| Protection helper | Go | One binary per platform |

This document covers building, testing, packaging, CI, and releases. For Electron-specific source layout and platform behavior, see [`desktop/README.md`](../desktop/README.md).

## Requirements

| Tool | Needed for | Version |
| --- | --- | --- |
| macOS + Command Line Tools | Native app | macOS 13+, Swift 6.x toolchain, macOS 26.5 SDK |
| Node.js + npm | Electron build | Node 22.12 or newer |
| Go | Protection helper | 1.23 or newer; CI uses 1.27.x |
| Platform toolchain | Packaging | Windows or Linux for the corresponding installer |

The native app is built and tested as **arm64**. The Electron app is built and packaged as **x64**.

## Native macOS app

### SDK requirement

The newer macOS 27 SDK shipped with Command Line Tools declares SwiftUI property wrappers such as `@State` as macros but does not include the `SwiftUIMacros` compiler plugin. ShieldBar builds against the macOS 26.5 SDK instead.

The build and test scripts default to:

```text
/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
```

Override it if your SDK is elsewhere:

```sh
export SHIELDBAR_SDK=/path/to/MacOSX26.5.sdk
```

### Build, sign, and install

```sh
Scripts/build-app.sh release
```

The script:

1. Builds the `ShieldBar` product with Swift Package Manager against `SHIELDBAR_SDK`.
2. Generates `Resources/AppIcon.icns` if it is missing (or if `FORCE_ICON=1`).
3. Runs `helper/build.sh` to cross-build the Protection helper for macOS, Windows, and Linux.
4. Assembles `~/Applications/ShieldBar.app` with the helper at `Contents/Resources/helper/shieldbar-helper`.
5. Ad-hoc signs the helper and the app, then verifies the signature.
6. Creates `~/Applications/ShieldBar.app.zip`.

Use `DEST` to install somewhere else:

```sh
DEST="$HOME/Desktop/ShieldBar.app" Scripts/build-app.sh release
```

There is no Developer ID signing step and no notarization. The resulting app is intended for local use and ad-hoc distribution.

### Tests

```sh
Scripts/test.sh
```

This runs the Swift Testing suite in `Tests/ShieldBarCoreTests` using the Command Line Tools framework paths. It covers the strict status evaluator, IP normalization, baseline capture, exact-IP hashing, location comparison, and Protection trigger selection.

### Live self-test

```sh
Scripts/self-test.sh
```

Or pass a specific app path:

```sh
Scripts/self-test.sh "/Applications/ShieldBar.app"
```

The self-test loads BrowserLeaks through the installed app, prints redacted addresses, and exits non-zero if a complete IP + WebRTC result cannot be read. A red or amber strict verdict is a valid finding, not a test failure.

### UI previews

```sh
~/Applications/ShieldBar.app/Contents/MacOS/ShieldBar \
  --render-preview /tmp/shieldbar-preview
```

The previews use documentation-only IP ranges and do not contact BrowserLeaks.

### Native app icon

`Resources/AppIcon.icns` is generated by `Scripts/build-app.sh` when missing. The vector renderer is `Scripts/make-icon.swift`; it draws the shield, then `sips` and `iconutil` produce the `.icns`. Force regeneration with:

```sh
FORCE_ICON=1 Scripts/build-app.sh release
```

## Protection helper

The helper is a small Go program in `helper/`. It requires no cgo and cross-compiles cleanly.

Build all three binaries into `desktop/resources/helper`:

```sh
helper/build.sh
```

or, from the Electron side:

```sh
cd desktop
npm run helper
```

Both produce:

```text
desktop/resources/helper/darwin-arm64/shieldbar-helper
desktop/resources/helper/win32-x64/shieldbar-helper.exe
desktop/resources/helper/linux-x64/shieldbar-helper
```

These binaries are generated artifacts and are ignored by git. Run the helper tests with:

```sh
cd helper
go test ./...
```

The tests use a fake backend to verify snapshotting, idempotent disable, restore-only-snapshot behavior, partial failures, and state retention. A `testmode` build tag provides a backend that refuses to touch interfaces outside the `sbtest`, `feth`, and `bridge` prefixes; it is available for safe manual or CI exercises of the real OS command paths.

## Electron app (Windows and Linux)

### Install dependencies

```sh
cd desktop
npm ci
npm run helper
```

`npm run helper` requires Go. Run it before `npm run dev`, `npm run build`, or any packaging command; the app expects the helper binaries under `resources/helper`, and the Protection installer reports a missing binary if they are absent.

### Develop and test

```sh
npm run dev        # development system tray/window
npm run typecheck
npm test           # Vitest unit tests, no network
npm run build      # main, preload, and renderer bundles
npm run smoke      # headless renderer/preload smoke test
npm run self-test  # live BrowserLeaks check, redacted output
npm run preview    # offscreen UI previews in desktop/preview/
```

`npm run smoke`, `npm run self-test`, and `npm run preview` run `npm run build` first. The live self-test exits non-zero when a complete IP + WebRTC result cannot be read; a red or amber verdict is a valid finding.

### Package

```sh
npm run dist:win    # NSIS installer + portable zip (x64)
npm run dist:linux  # AppImage + .deb (x64)
```

Artifacts are written to `desktop/release/`:

| Asset | Format |
| --- | --- |
| `ShieldBar-1.1.1-win-x64.exe` | Per-user NSIS installer |
| `ShieldBar-1.1.1-win-x64.zip` | Portable zip |
| `ShieldBar-1.1.1-linux-x86_64.AppImage` | AppImage |
| `ShieldBar-1.1.1-linux-amd64.deb` | Debian package |

The version comes from `desktop/package.json`. Packaging is unsigned and uses `CSC_IDENTITY_AUTO_DISCOVERY=false` in CI. There is no auto-updater.

Cross-packaging is only partially supported. Build Windows artifacts on Windows and Linux artifacts on Linux; GitHub Actions does both reliably.

### Electron icons

```sh
npm run icons
```

The script extracts the largest representation from `Resources/AppIcon.icns` with `sips` when available, otherwise draws the vector fallback. It generates:

- `desktop/build/icon.ico` for Windows
- `desktop/build/icons/` for Linux
- `desktop/resources/tray/` status icons in every state
- `desktop/build/icon.png` and `desktop/resources/icon.png`

The script is idempotent.

## CI

`.github/workflows/desktop-build.yml` runs on:

- pushes to `main` that touch `desktop/**` or the workflow file
- manual `workflow_dispatch`
- `v*` tags

Jobs:

1. **Test (Ubuntu):** Node 22, Go 1.27.x, `npm ci`, typecheck, Vitest, `go test ./...`, bundle build, headless Electron smoke test, and a non-blocking live BrowserLeaks self-test.
2. **Package (Windows and Ubuntu matrix):** builds the helper, builds the bundles, packages the x64 targets, smoke-tests the unpacked executable, and uploads artifacts.
3. **Draft release (tag pushes):** downloads the artifacts, generates `SHA256SUMS.txt`, and creates a draft GitHub release with `gh release create --draft`.

No code-signing secrets are used. Windows and Linux artifacts are unsigned; the macOS build is ad-hoc signed locally and is not built by this workflow.

## Release process

1. Update the version in:
   - `Resources/Info.plist` (`CFBundleShortVersionString` and `CFBundleVersion`)
   - `desktop/package.json` (and the lockfile)
   - `helper/protocol.go` (`helperVersion`)
   - the README badges, download table, and asset names
2. Run the native and Electron test suites, plus both self-tests on a machine with working network access.
3. Build the macOS app locally and create its zip (`Scripts/build-app.sh` writes `ShieldBar.app.zip`). Run `Scripts/self-test.sh` against the installed bundle.
4. Commit the version bump and tag it, for example `v1.1.1`.
5. Let CI create the draft release with the Windows and Linux assets and `SHA256SUMS.txt`.
6. Attach the macOS arm64 zip manually as `ShieldBar-1.1.1-macos-arm64.zip`. Because CI generated the checksum file before the macOS asset existed, add the macOS checksum and upload the updated `SHA256SUMS.txt`.
7. Smoke-test the installers on clean Windows, Linux, and macOS machines or VMs.
8. Publish the draft.

### Artifact contents

| Asset | Contents |
| --- | --- |
| macOS zip | `ShieldBar.app` with the embedded helper at `Contents/Resources/helper/shieldbar-helper`; ad-hoc signed |
| Windows installer | Per-user NSIS install with the bundled helper |
| Windows portable zip | Unpacked app and helper; no installer or Start Menu shortcut |
| Linux AppImage | Self-contained app and helper; requires FUSE unless extracted |
| Linux `.deb` | System package with the app and helper |
| `SHA256SUMS.txt` | SHA-256 checksums for the release assets |

## Signing caveats

- **macOS:** ad-hoc signed, not notarized. Gatekeeper may require Control-click → Open. There is no Apple Developer ID.
- **Windows:** unsigned. SmartScreen warns about an unknown publisher.
- **Linux:** packages are unsigned.
- **Updates:** no auto-update. Users must download a new release.

Do not describe any build as Developer ID signed, notarized, or auto-updating unless that signing and update infrastructure actually exists. The macOS build is ad-hoc signed only.
